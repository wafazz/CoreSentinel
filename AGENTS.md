> For the agent or engineer changing **this repository**. If you are looking for
> how CoreSentinel governs *your* project, read [`README.md`](./README.md).

> `coresentinel adapter sync` and carries a `CORESENTINEL:MANAGED` marker. This

## 1. The one rule

**Nothing reports a result it did not measure.**

Every other convention here follows from that. CoreSentinel exists because AI
agents state claims with total confidence and no evidence; a governance tool
that does the same is worse than none, because it looks like a control.

This is not aspirational. v1 shipped a verifier that awarded 45 of 100 points
from three checks that executed nothing, and a health scorecard that invented
five of seven dimensions from constants. An **empty directory** scored 80/100
`VERIFIED` on the claim *"I fixed the authentication vulnerability"*. Phases 1–11
removed that, and the suite now fails if it comes back.

Concretely, when you add anything that produces a number or a status:

| Situation | Correct result | Never |
| :--- | :--- | :--- |
| The check ran and passed | `PASS` with command, exit code and output digest | `PASS` with a justification string |
| The check ran and failed | `FAIL` with the same evidence | silence |
| The tool is not installed | `UNKNOWN`, excluded from the aggregate | `PASS`, or `0` |
| Nothing has exercised it yet | "never observed" | `0` |

`UNKNOWN` and `0` are different claims. `0` means *measured, and it was none*.
`UNKNOWN` means *nobody measured*. Rendering them the same way is the bug.

## 2. Layout

```text
coresentinel.py            CLI entry point — command registry, dispatch, rendering
coresentinel_*.py          v1 engines (memory, recall, lifecycle, gates, score, …)
coresentinel_core/         the v2 package
├── runtime/               config · container · events · logging · paths · errors
├── storage/               ports · json_store · sqlite_store · migrations/
├── memory/                assembly (task-relevant context packs)
├── decisions/             ledger · schema · contradiction guard
├── knowledge/             entities · relations · graph
├── project/discovery/     language, framework, datastore, CI, container detection
├── agents/                protocol · registry · permissions · sandbox · orchestrator
│   └── adapters/          base · cli_agent · http_agent · mcp_agent
├── verification/          (in coresentinel_evidence.py) checks with real commands
├── incidents/ patterns/ learning/ audit/    governance ledgers
├── observability/         metrics · budgets
├── security/              redaction
├── services/facade.py     THE service layer — every surface calls this
├── api/server.py          HTTP API, generated from the catalogue
├── mcp/server.py          MCP server, generated from the same catalogue
└── web/                   static dashboard, no build step
```

**Why the engines are still flat `coresentinel_*.py` files.** A package directory
named `coresentinel/` shadows `coresentinel.py` on import — packages win over
modules — which breaks `import coresentinel as cli` and every integration test.
The v2 package is therefore `coresentinel_core/`. Phase 3 also tried relocating
the memory engines behind re-export shims and found the shims silently break the
test isolation those engines depend on. They stayed where they are, deliberately.

## 3. Architecture, in four facts

**1. Surfaces may only call services.** The CLI, HTTP API, MCP server and
dashboard all go through `coresentinel_core/services/facade.py`. None may touch
`storage/` or an engine directly. This is enforced by an import-graph test, not
by convention — `tests/surfaces/test_governance_bypass.py` fails the build if
`api/` or `mcp/` imports storage.

**2. Operations are declared once and appear everywhere.** `Services.OPERATIONS`
maps a name to `(mode, method)`. The API's routes and MCP's tools are *generated*
from it, so an operation exists on every surface or on none. Adding a verb to
one surface only is not possible by construction.

**3. Emitting an event is how something gets audited.** The audit ledger
subscribes to the event bus. A subsystem that emits is recorded; one that does
not shows as an unrecorded subject in `coresentinel audit coverage`. Never call
the ledger directly from feature code.

**4. Two stores, split by access pattern, not reversed.** ADR-001 chose
file-based JSON and that still holds for anything a human reads, commits and
diffs — memory layers, decisions, the journal. SQLite holds append-heavy machine
records: audit events, verification runs, health snapshots, metrics. **Deleting
the database loses no memory, no decision and no journal entry**, and a test
asserts the schema contains no table for them.

## 4. How to add a…

### …command

1. Write `cmd_<name>(args)` in `coresentinel.py`. Return an int exit code, or
   `None` for 0.
2. Add an entry to the `COMMANDS` list: `name`, `aliases`, `group`, `handler`,
   `summary`, `usage`, `detail`.
3. **If it reads a flag's value, add that flag to `VALUE_FLAGS`.** Miss this and
   `free_args()` treats the value as a positional argument — that is how
   `verify --claim "fixed the login bug"` came to verify a directory named after
   the claim (F-20, and again as F-23). A source-scanning test enforces it.
4. Support `--json` if it returns data. stdout carries the payload, stderr
   carries diagnostics — always, so a damaged Core still emits parseable JSON.
5. Document it in `14-cli-protocol.md`. `tests/documentation/` fails the build
   if the docs name a command that does not exist, or if a registered command is
   documented nowhere.

### …service operation

1. Add a method to `Services`. Return plain JSON-serialisable data — no engine
   objects leak out.
2. Register it in `Services.OPERATIONS` with `READ` or `WRITE`.
3. A write must `self._emit(...)` an event, or it will not be audited.
4. **If it returns a collection, page it.** Use `clamp_page()` and `_page()` or
   `_window()`, and return a `page` block. `tests/performance/test_pagination.py`
   derives its requirement from the catalogue, so an unpaged list operation fails
   the day you add it. If it genuinely returns a fixed enumeration, add it to
   `UNPAGED_BY_DESIGN` **with a reason**; a test re-checks that the reason holds.
5. The route and the MCP tool appear automatically. Do not hand-write either.

### …storage collection

1. Add the name to `COLLECTIONS` in `storage/ports.py`.
2. Add a numbered migration `NNNN_name.sql`. Contiguous from 0001, `IF NOT
   EXISTS`, forward-only. **Editing an applied migration is refused** — the
   checksum is recorded, and the reverse of a bad migration is a new one.
3. Add promoted columns to `PROMOTED` in `sqlite_store.py` if you need to index
   or filter on them. Everything else round-trips inside the payload.
4. Both backends must satisfy the same contract suite in
   `tests/runtime/test_storage_port.py`, which is parametrized over both.

### …agent adapter

1. Subclass the base in `agents/adapters/`, implement invoke and normalise.
2. Add the host to `adapters.json` — a registry entry, not code.
3. Pass the conformance suite in `tests/agents/test_adapters.py`. Test against a
   mock, never a vendor: a test that needs Claude installed does not run in CI.

### …test

1. Put it in the package matching the **subsystem**, not the file it touches.
2. Use the fixtures. Never construct a path into the real `memory/`.
3. Assert behaviour that would harm a user if it broke, not formatting.
4. If it pins a fixed bug, say so in the name or docstring — the regression
   should be legible years later.
5. **A test may be added to, never weakened.** Removing an assertion to make a
   build pass is the failure this project is about.

### …protocol document

Numbered `NN-name.md`, linked from `00-identity.md`. `doctor` counts them and
`tests/governance/test_protocol_integrity.py` asserts every index link resolves.

## 5. Traps this codebase has already fallen into

Each of these is a real defect that shipped. They are listed because they are
the mistakes most likely to be repeated.

| Trap | What happened |
| :--- | :--- |
| **Hardcoding a PASS** | Three of six evidence checks and five of seven health dimensions were constants. Now behaviourally asserted — a grep would miss a constant reached through a variable |
| **Invoking `python`** | Absent on macOS and Debian with only `python3`. Use `coresentinel_exec.python()`. A test proves no code path calls it by name |
| **`shell=True`** | Six modules interpolated paths into shell strings. One argv-list executor now; its absence is ast-asserted |
| **Printing to stdout from a library** | The scanner logged to stdout and corrupted every `--json` payload of anything reusing it in-process. Diagnostics go to stderr |
| **Reading the whole collection to write one record** | `_next_id` called `count()` called `all()`, and the audit ledger re-read the trail to append. Cost per record rose 11.4x at 4,000 records. Budget `audit.append_scaling_ratio` guards it |
| **Resolving a path per item** | Context assembly resolved the project binding once per fact — 80,123 stat calls for one pack. Loop-invariant lookups get hoisted; `find_project_root` caches |
| **Over-broad redaction** | `auth` matched `author` and `authority`; `pass` matched `tests_passed`. The audit trail destroyed real records to protect nothing. Over-redaction is silent — check both directions |
| **A silent cap** | Truncating, sampling or dropping without saying so reads as complete coverage. Say what was dropped |

## 6. Before you claim it works

```bash
python -m pytest tests -q                # every test, none removed
python sentinel-validator.py             # secrets & anti-patterns, exit 0
python coresentinel.py doctor            # 10 subsystems
python coresentinel.py review            # static pass over added lines
python coresentinel.py verify --claim "…"  # evidence-based, exit 0/1/2
python coresentinel.py metrics budgets   # published performance limits
```

Exit codes: **0** pass · **1** fail · **2** indeterminate (a check could not
run). `2` is not a softer `1` — it means the question was not answered.

If a fixture file must contain a credential-shaped string, mark it
`CORESENTINEL:SCANNER-FIXTURES` in the first 20 lines, and **assemble the value
at runtime from parts** rather than writing the literal. GitHub's push
protection scans blob content and cannot tell a fixture from a live key; it
rejected this repository once for exactly that.

## 7. Changing a rule

Rules in `anti-patterns.json` are not edited by hand. They go through the
Controlled Self-Evolution pipeline:

```bash
coresentinel evolve propose --target anti-patterns.json --change "…" --evidence "…"
coresentinel evolve list
coresentinel evolve approve EVO-00N --approver "<human>"
coresentinel evolve apply EVO-00N
```

**Nothing auto-approves, and a hard regression test asserts it.** `apply` refuses
any status but `APPROVED`, snapshots before writing, bumps the registry version,
and `revert` restores byte-identically. Candidates require evidence from at least
two incidents, so the pipeline cannot train you to rubber-stamp.
